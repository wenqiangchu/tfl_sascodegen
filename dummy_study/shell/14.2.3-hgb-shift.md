### 为什么用 `LBNRIND` 而不是 `BNRIND`/`ANRIND`

`ADLBH` 的 `BNRIND`/`ANRIND` 在 HGB 的基线记录上**全部是 `'N'`**（247 例无一例外），
所以按 3 列（N/L/H）做 shift 会退化成只有一列有数据。

`LBNRIND`（本地实验室参考范围指示）有真实分级变化：HGB 基线 235 `NORMAL` / 9 `LOW` /
3 `HIGH`，基线后出现 133 条 `LOW`、12 条 `HIGH`。因此本表用 `LBNRIND` 作为分级来源。
`ADLBH` 没有 `ANRLO`/`ANRHI` 列，无法从数值自行推断分级，只能用这个现成指示变量。

### 关键实现细节

1. **分级顺序**：`NORMAL < LOW < HIGH`（rank 0/1/2）。这个顺序是本表**声明**的，
   不是从数据推断的；`HIGH > LOW` 只是为了让「最差」有唯一解，不代表临床严重度排序。
2. **没有基线后分级时沿用基线分级**：5 例受试者有基线记录但没有任何基线后分级记录
   （`01-703-1279` 基线 HIGH，另 4 例基线 NORMAL）。规则是
   `if missing(W_RANK) then W_RANK = BL_RANK;`，语义为「没有观察到变化」。
   这样每个 section 的三行之和恰好等于该组的基线人数（85 / 81 / 81），可直接断言。
   若改为「无基线后值则不计入任何行」，Low Dose 组会差 1 例（那个基线 HIGH 的受试者）。
3. **基线只取 `ABLFL = 'Y'` 的那条记录**，不按 `ANL01FL` 过滤（`ANL01FL` 在基线行为空）。
4. 5 例的合计：247 例有基线分级，254 例有 HGB 数据，7 例无基线记录被排除。

### `custom_code.before`（派生 `WORK.SHIFT_HGB`）

```sas
/* Baseline grade: one record per subject from the ABLFL='Y' row. */
proc sql;
  create table work.bl as
    select USUBJID,
           TRTA,
           LBNRIND as LBNRIND_BL,
           case LBNRIND when 'NORMAL' then 0 when 'LOW' then 1 when 'HIGH' then 2 end as BL_RANK
    from study.adlbh
    where PARAMCD = 'HGB' and ABLFL = 'Y';
quit;

/* Worst post-baseline grade: maximum declared rank across all post-baseline rows. */
proc sql;
  create table work.worst as
    select USUBJID,
           max(case LBNRIND when 'NORMAL' then 0 when 'LOW' then 1 when 'HIGH' then 2 end) as W_RANK
    from study.adlbh
    where PARAMCD = 'HGB' and ABLFL ne 'Y'
    group by USUBJID;
quit;

/* Subjects without any post-baseline grade keep their baseline grade. */
proc sql;
  create table work.shift_hgb as
    select b.USUBJID,
           b.TRTA,
           b.LBNRIND_BL,
           coalesce(w.W_RANK, b.BL_RANK) as W_RANK
    from work.bl as b
    left join work.worst as w
      on b.USUBJID = w.USUBJID;
quit;

data work.shift_hgb;
  set work.shift_hgb;
  length ANRIND_WORST $8;
  select (W_RANK);
    when (0) ANRIND_WORST = 'NORMAL';
    when (1) ANRIND_WORST = 'LOW';
    when (2) ANRIND_WORST = 'HIGH';
    otherwise ANRIND_WORST = '';
  end;
run;
```

**P5 断言**：
- 每个 section 的三行之和 = 该 section 的基线人数（85 / 81 / 81）；
- 三个 section 的合计 = 235 / 9 / 3（即 Header 列 N）；
- Placebo 的 High 列全为 0 且必须显示 `0 (0.0%)`。

## 6. Open points / 脚注

- **N 与 % 的口径（已确认）**：采用 **(a) 保留三个 section，百分比用组内分母**。
  Header 的 N 行是全人群（235 / 9 / 3 / 247），组内百分比的分母是该治疗组的基线人数
  （82/3/0 等），行和等于该组基线人数。两个口径不同，需在报告脚注声明。
  - 曾被考虑并否决的两种替代：(b) 拆成 3 张独立表（输出从 1 张变 3 张，偏离参考 shell）；
    (c) 三列都用全人群分母（会让 Placebo 的 High 列显示 `0/3`，而该组实际无基线 High 受试者）。
- 由于 Header 只由一个 source 派生，同一张表内无法为不同 section 显示不同的 N；
  因此组内 N 在 §3 的表格和脚注里声明，不靠列头。
- 分级顺序 `NORMAL < LOW < HIGH` 是声明式约定，不是临床严重度。
- `LBNRIND` 另有 `ABNORMAL` 取值（其他参数出现 427 条），本参数没有；若数据出现，
  `case` 表达式会得到缺失，`ANRIND_WORST` 为空，该受试者不落入任何行——
  这是一条需要显式处理的已知边界。
