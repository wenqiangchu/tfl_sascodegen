# 14.3.2.1 血红蛋白按访视（Hemoglobin by Visit）

## 1. Identity

| 项 | 值 |
| --- | --- |
| 表号 | 14.3.2.1 |
| 标题 | Hemoglobin (mmol/L) by Visit |
| 分析人群 | Safety（`safety`，`SAFFL = 'Y'`，254 例） |
| 来源数据集 | `adlbh` |
| Header | `actual_treatment`（`TRT01A`） |
| 输出 | RTF（横版） |

**本表的排序必须用 `order_variable: AVISITN`，不能用 `format`。** `AVISIT` 是字符串，
字母序会排成 `Baseline, End of Treatment, Week 12, Week 16, Week 2, Week 20, ...`——
`Week 12` 跑到 `Week 2` 前面。P4 实测：只要 level 声明了 `format`，emitter 就走
「format 目录」路径（`src/emitters/hierarchical.R:285`）并**静默忽略**
`order_variable`/`order_direction`，节点按未格式化值升序排列，于是访视仍然是字母序。
所以本表改用 `AVISITN`（Baseline=0、Week 2=2 … Week 26=26、End of Treatment=99）。

「完整节点集合」这条验证已移到 14.3.1.4 的 `TFLSEV`（`4 = 'LIFE THREATENING'`），
因为同一个 level 上无法同时拥有 format 的顺序语义和 order_variable 的顺序语义。

### 关键实现细节

1. **不能加 `ANL01FL = 'Y'` 过滤。** 本数据的 `ANL01FL` 只标在 306 条基线后记录上，
   Baseline 行的 `ANL01FL` 为空。若按 `ANL01FL = 'Y'` 过滤，Baseline 节点会整行消失，
   且只剩 9 次访视——这正是最初草案里的错误，已在本 shell 修正。
2. **46 条记录的 `AVISIT` 为空**（2052 条 HGB 记录里 2006 条有访视）。`missing_policy`
   设为 `exclude`，这些记录不参与统计，也不生成 Missing 节点。
3. **`AVAL` 无缺失**（2052 条全部有值），所以 `n` 等于该访视的记录数。

### 排序键（`AVISITN`），不是 `format`

本表**不使用** `PROC FORMAT`。访视顺序由 `order_variable: 'AVISITN'` 给出：

| 访视 | `AVISITN` |
| --- | ---: |
| Baseline | 0 |
| Week 2 / 4 / 6 / 8 | 2 / 4 / 6 / 8 |
| Week 12 / 16 / 20 / 24 / 26 | 12 / 16 / 20 / 24 / 26 |
| End of Treatment | 99 |

升序即临床顺序，且 `End of Treatment` 因为 99 自然排在最后。

**P5 断言**：
- 11 个访视节点的顺序为上表顺序（不是字母序 —— 字母序会把 `Week 12` 排到 `Week 2` 前）；
- 各节点的 `n` 与上表「预期参与记录数」相等。

## 5. Chunk plan

```yaml
- id: 'hgb_by_visit'
  type: 'hierarchical_summary'
  source_data: 'study.adlbh'
  filter: 'PARAMCD = ''HGB'''
  levels:
    - id: 'param'
      variable: 'PARAM'
      label_variable: 'PARAM'
      order_variable: 'PARAM'
      order_direction: 'asc'
      node_role: 'label'
      missing_policy: 'exclude'
    - id: 'visit'
      variable: 'AVISIT'
      label_variable: 'AVISIT'
      order_variable: 'AVISITN'    # 不能用 format：会静默忽略 order_variable
      order_direction: 'asc'
      node_role: 'label'
      missing_policy: 'exclude'
  analysis_blocks:
    - id: 'aval'
      anchor_level: 'visit'
      placement: 'below'
      type: 'continuous_summary'
      counting_unit: 'record'
      analysis_variable: 'AVAL'
      rows:
        - id: 'stats'
          type: 'analysis'
          label: 'n'
          statistics:
            - id: 'n'
            - id: 'mean'
              digits: 2
            - id: 'sd'
              digits: 2
            - id: 'median'
              digits: 2
            - id: 'q1'
              digits: 2
            - id: 'q3'
              digits: 2
            - id: 'min'
              digits: 2
            - id: 'max'
              digits: 2
          cell_format: '{n} {mean} ({sd}) {median} ({q1}, {q3}) {min}, {max}'
```

注意 `visit` level **不声明 `format`**。`parse_level_value` 允许「有 `format` 时省略
order 字段」，但 P4 实测 emitter 在 `format` 分支里直接忽略 `order_variable`
（`src/emitters/hierarchical.R:285` 提前返回），所以「format + order_variable」不会按
后者排序。两者互斥：**要顺序用 `order_variable`，要完整节点集合用 `format`**。

## 6. Open points / 脚注

- **完整节点探针已移到 14.3.1.4 的 `TFLSEV`（`4 = 'LIFE THREATENING'`）。** 原计划放在
  本表的 `$TFLVISIT`（`Week 28`），但 P4 发现 `format` 一旦声明就会接管整个 level 的
  节点构造并忽略 `order_variable`，访视便只能按字母序排列。二者不可兼得，所以访视层
  改用 `AVISITN` 保证顺序，探针迁到一个封闭取值域（严重度代码）里继续验证完整性。
  这是对「Week 28 保留」这一已确认决定的**修订**，需要你复核。
- `counting_unit = record` 与 `distinct_subject` 在本数据上结果相同（每例每次访视一条
  记录），选 `record` 是为了表达「按记录汇总」的语义；若数据出现重复访视记录，
  两者会分叉——这属于需要单独设计决策的情形。
- 分位数在 P5 只报告不判定（理由同 14.1.2）。
